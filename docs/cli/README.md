# The `praxis` command line

`praxis` drives Praxis Sound without the window: plan a sound from a brief, edit it bar by bar,
render, check, analyse reference clips, match them, export. Agents and video pipelines use it (and
the MCP server `praxis-mcp`, which calls the same command layer, `praxis_cli::ops`). A take made
here appears live in the desktop app when it has the same sound open.

- [commands.md](commands.md): every command, its arguments (from `--help`), and a real JSON
  result from the release build (generated by `python -I docs/cli/generate.py`).
- [../contracts/cli.md](../contracts/cli.md): the frozen JSON contract, field by field.
- [../agents/praxis-skill/SKILL.md](../agents/praxis-skill/SKILL.md): the guide for agents
  (how to plan, edit and check sounds well).

## Build and run

```bash
cargo build --release -p praxis-cli          # target/release/praxis(.exe)
praxis --help
praxis <command> --help
```

## JSON output

Add `--json` (anywhere on the line) and every command prints exactly one JSON object on stdout:

```json
{"ok": true, "command": "render", ...payload}
{"ok": false, "command": "render", "error": {"code": "io", "message": "...", "issues": [...]}}
```

Payloads only gain fields between versions, never lose or rename them. Progress words (the sound
assistant's steps) go to stderr, never stdout. Argument errors with `--json` are JSON errors too
(code `error`). Without `--json` the output is readable text and may change.

**Exit codes.** 0 on success; 1 on any error; `check` also exits 1 when a check fails (the payload
is still printed with `passed: false`). A turn of the sound assistant that ends in a question or a
reply without a take is a success (exit 0, `take: null`, `no_take` says why).

**Error codes** (`error.code`):

| Code | Meaning |
| --- | --- |
| `io` | a file or folder could not be read or written (path in the message) |
| `bad_json` | not valid JSON, or not the expected shape (a ScorePlan, EditPlan, ScorePatch) |
| `bad_score` | JSON that is not a Score or project |
| `invalid_score` | a Score that fails validation; `issues[]` has `code, path, message` |
| `bad_format` | unknown audio format or sample rate |
| `render_failed` | the engine could not render |
| `pack_missing` | an instrument needs a pack that is not installed (`praxis packs install ...`) |
| `pack_verify_failed` | a pack download is not the archive the index names (size or blake3) |
| `decode_failed` | an audio/video clip could not be decoded |
| `patch_rejected` | an edit was refused (scope, locked layer, nothing to change); `issues[]` say why |
| `no_api_key` | `--provider claude` without an Anthropic API key |
| `provider_failed` | the Claude API failed |
| `error` | anything else (bad arguments, unknown names) |

## Environment

| Variable | Default | Use |
| --- | --- | --- |
| `PRAXIS_HOME` | `%USERPROFILE%\Praxis Sound` (`$HOME/Praxis Sound`) | sounds (`sounds/<name>`), the reference library (`library/`), crash reports (`logs/`) |
| `PRAXIS_PACKS` | a `packs/` folder with an `index.json` near the current folder or the executable | instrument packs |
| `ANTHROPIC_API_KEY` | none (then the OS keychain, `praxis key set`) | the sound assistant and the Claude planner; without a key the offline planner answers |
| `PRAXIS_KEYCHAIN` | on | `off` ignores the keychain (tests, CI) |
| `PRAXIS_FFMPEG` | an `ffmpeg` on an absolute `PATH` entry | decoding M4A/AAC/MP4/MOV/WebM (optional; WAV, FLAC, OGG and MP3 need nothing) |
| `PRAXIS_CLAUDE_URL` | the Anthropic API | a local stand-in for tests; loopback addresses only |

A **sound** argument is a folder path, or a bare name kept under `PRAXIS_HOME/sounds/`.

## Crash reports

If `praxis`, `praxis-mcp` or the app crashes, a plain-text report is written to
`PRAXIS_HOME/logs/crash-<UTC time>-<pid>.txt` (or `%LOCALAPPDATA%\Praxis Sound\logs` when that
folder cannot be created) and its path is printed on stderr. Nothing is uploaded. It holds the
program, version, OS, the panic message and a backtrace; no audio, no sounds, and anything shaped
like an API key is removed. To report a crash, attach that file to an email or issue. The newest
20 reports are kept. The app shows a notice with the path the next time it starts.

## A first session

```bash
praxis packs install upright-piano-kw                       # the felt piano (33 MB, CC0)
praxis ask calm "a calm felt piano loop in A minor, 16 bars at 128 BPM, soft kick from bar 9" --provider offline
praxis ask calm "make it softer" --bars 13-16 --layer piano --provider offline
praxis takes calm --json                                    # the history, current take, checks
praxis export-midi "%USERPROFILE%\Praxis Sound\sounds\calm\project.praxis" -o calm.mid
praxis bench                                                # this machine's render speed
```

With an API key, leave out `--provider offline` and the sound assistant (Claude) carries out the
request with the same tools.
